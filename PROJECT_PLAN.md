# StarBoy — Project Plan

> Подробный план разработки. Этапы идут последовательно, но внутри этапа задачи могут параллелиться. Отмечай выполненное `[x]` и коммить изменения.

---

## Этап 0 — Подготовка окружения и проекта

> Цель: иметь рабочий PlatformIO-проект, готовый к компиляции, с корректным `platformio.ini` под нашу плату.

- [x] Установить VS Code (.deb версия)
- [x] Установить PlatformIO IDE Extension
- [x] Добавить пользователя в группы `dialout`, `plugdev`
- [x] Установить udev-правила PlatformIO
- [x] Создать структуру папок проекта `~/code/LILBRO/`
- [x] Создать PlatformIO-проект `starboy-firmware` (board: esp32-s3-devkitc-1, framework: arduino)
- [x] Адаптировать `platformio.ini` под нашу плату:
  - PSRAM: OPI 8MB
  - Flash: 8MB
  - CPU: 240MHz
  - Partition scheme: с большим APP-разделом для будущих библиотек
  - Monitor speed: 115200
  - Build flags: для PSRAM, USB CDC и т.д.
- [x] Настроить `.gitignore` (исключить `.pio/`, `.vscode/` кроме настроек проекта, `secrets.h`)
- [x] `git init`, первый коммит «initial PlatformIO project»
- [x] Создать `secrets.example.h` с шаблоном (Wi-Fi SSID/PASS, API keys placeholders)
- [x] Сделать тестовый `main.cpp` с `Serial.println("StarBoy boot")`
- [x] Проверить компиляцию: `pio run` должен пройти без ошибок (прошивать пока некуда)

**Definition of Done:** `pio run` выдаёт `[SUCCESS]`, проект закоммичен в git, структура папок соответствует CLAUDE.md.

## Этап 1 — BOM и закупка железа

> Цель: к моменту приезда платы все компоненты уже в пути.

- [ ] Составить полный BOM с ссылками на магазины (AliExpress / DigiKey / Amazon — что доступно)
- [ ] Гироскоп: LSM6DS3 breakout (приоритет) или MPU6050
- [ ] Динамик 8Ω 2W с MX1.25 разъёмом (или с пайкой)
- [ ] Li-Po аккумулятор 3.7V с MX1.25, ~500-800 mAh подходящего форм-фактора
- [ ] Кабель SH1.0 12-pin
- [ ] Прототипная макетка + DuPont провода для тестового подключения
- [ ] (Опционально) Логический анализатор / USB-osciлоskoп для отладки I2C/SPI
- [ ] Заказать всё, отметить ETA каждого

**Definition of Done:** все компоненты заказаны, BOM сохранён в `hardware/BOM.md` со статусом каждого.

## Этап 2 — Первый запуск платы

> Цель: плата приехала, прошивается, дисплей светится.

- [ ] Получить плату физически
- [ ] Скачать примеры Waveshare с их wiki для ESP32-S3-Touch-AMOLED-1.32
- [ ] Изучить какие библиотеки Waveshare использует (CO5300 driver, CST820 driver, LVGL версия)
- [ ] Подключить плату по USB-C
- [ ] Проверить: `pio device list` показывает /dev/ttyACM0 или /dev/ttyUSB0
- [ ] Прошить blink-тест (Serial вывод + одна цветная заливка экрана)
- [ ] Проверить serial monitor: `pio device monitor`

**Definition of Done:** плата прошивается, экран показывает заливку, в serial видны логи.

## Этап 3 — Дисплей и базовые глазки

> Цель: на экране плавно анимируются глазки минимум 30 fps, есть несколько эмоций.

- [ ] Интегрировать драйвер CO5300 (от Waveshare или аналог)
- [ ] Настроить буфер кадра в PSRAM
- [ ] Решить: рисуем напрямую или через LVGL? (рекомендация: LVGL для UI, прямой рендер для глазок-анимации)
- [x] Создать модуль `eyes/` с классом Eyes:
  - setEmotion(Emotion) — IDLE, HAPPY, ANGRY, SAD, SLEEPY, SURPRISED
  - lookAt(x, y) — для слежения за наклоном
  - triggerBlink() — ручное моргание
  - update() — вызывается из FreeRTOS каждые 33 мс
- [x] Реализован процедурный рендер глазок (не спрайты — см. display-driver-research.md)
- [x] Анимация моргания (каждые 2-5 секунд, рандомный интервал, 300 мс цикл)
- [x] FreeRTOS-задача для render loop ~30 fps на Core 1
- [ ] Тачскрин CST820: интегрировать драйвер, на тач — показать другую эмоцию

**Definition of Done:** на устройстве 30+ fps плавная анимация глазок, реакция на тач, переключение эмоций.

## Этап 4 — Звук (микрофон + динамик)

> Цель: записываем звук с встроенного микрофона, проигрываем тестовый wav на динамике.

- [ ] Подключить динамик к разъёму платы
- [ ] Настроить I2S и ES8311 (Codec init)
- [ ] Записать 5 секунд аудио с микрофона в PSRAM
- [ ] Проиграть записанное на динамике (echo-test)
- [ ] Проиграть встроенный wav-файл из flash
- [ ] Реализовать модуль `audio/` с интерфейсом записи/воспроизведения

**Definition of Done:** echo-test работает, динамик играет встроенный звук без искажений.

## Этап 5 — Wi-Fi и облачный AI

> Цель: голос с микрофона уходит в облако, ответ возвращается голосом.

- [ ] Реализовать Wi-Fi connect manager (с conf-режимом для смены сети)
- [ ] **Принять решение по AI-провайдеру** (обсудить с пользователем)
- [ ] Интегрировать STT (Whisper API или локальный wake-word через esp-sr)
- [ ] Интегрировать LLM API
- [ ] Интегрировать TTS API (ElevenLabs, Google TTS, или альтернативы)
- [ ] Создать «персональность» через системный промпт (первая модель — нейтральный characterful AI)
- [ ] Полный цикл: нажал кнопку → сказал → ИИ обработал → ответил голосом
- [ ] Глазки реагируют: думает (loading), говорит (mouth-mode), слушает (focused)

**Definition of Done:** работает полный диалог через облако с задержкой <3 секунд.

## Этап 6 — Сенсоры (гироскоп)

> Цель: устройство реагирует на тряску, наклон, переворот.

- [ ] Подключить LSM6DS3 / MPU6050 к I2C
- [ ] Драйвер сенсора, чтение акселерометра + гироскопа
- [ ] Детекция тряски (shake detection)
- [ ] Детекция переворота (upside-down)
- [ ] Детекция «лежит на столе» (flat) для sleep-режима
- [ ] Реакции в глазках: тряхнули → шок/злость, перевернули → спать, наклон → зрачки следят

**Definition of Done:** все жесты определяются и вызывают соответствующие реакции глазок.

## Этап 7 — Личности и управление состоянием

> Цель: разные системные промпты для разных серий, выбор личности при инициализации.

- [ ] Архитектура состояния устройства (mood, energy, hunger?, last_interaction)
- [ ] Загрузка системного промпта из конфига при старте
- [ ] 3-5 разных личностей: милый / дерзкий / серьёзный / меланхоличный / весёлый
- [ ] Отражение «настроения» в выборе глазок-эмоции по умолчанию

**Definition of Done:** одно устройство ведёт себя как один из 3-5 характеров стабильно между перезагрузками.

- [ ] BLE Advertising с уникальным ID устройства

## Заметки и решения

### ADR (Architecture Decision Records)

Сюда записываем важные архитектурные решения с обоснованием. Формат:

```
## ADR-001: Гибридная AI-архитектура (облако, не локально)
Дата: 2026-05-08
Контекст: ESP32-S3 имеет 8МБ PSRAM, локальная LLM не помещается.
Решение: STT/LLM/TTS через облачные API, локально — только wake-word.
Последствия: требуется Wi-Fi, есть задержка ~1-3с, нужны API-ключи.
Альтернативы: ждать более мощную плату, использовать смартфон как мост.
```

(заполняй по мере принятия решений)
