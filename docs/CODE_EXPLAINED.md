## Как устроена прошивка вообще

Прошивка — это программа, которая живёт внутри платы и запускается каждый раз при включении. Она написана на C++ в стиле Arduino.

У любой Arduino-программы есть два обязательных блока:

```
setup()  — выполняется ОДИН РАЗ при включении
loop()   — выполняется ВЕЧНО, по кругу, пока плата включена
```

Это как: setup = «встать, умыться, одеться», loop = «дышать» (бесконечно).

## Файлы проекта и что они делают

### `platformio.ini` — главный конфиг проекта

Это как паспорт проекта. Он говорит PlatformIO:
- **Какая у нас плата** (`board = esp32-s3-devkitc-1`)
- **Какой фреймворк** (`framework = arduino`) — пишем как для Arduino, хотя плата мощнее
- **Насколько быстрый процессор** (`f_cpu = 240000000` — 240 миллионов операций в секунду)
- **Сколько памяти** (8 МБ Flash для кода + 8 МБ PSRAM для данных)
- **Какие библиотеки нужны** (GFX — рисовать на экране, LVGL — делать интерфейс)
- **На каких ногах (GPIO) что висит** — каждый пин платы имеет номер, и мы говорим коду «нога 10 — это выбор дисплея», «нога 47 — это шина I2C»

```
GPIO — General Purpose Input/Output.
Просто пронумерованные контакты на плате.
Каждый можно назначить для разного: UART, I2C, SPI, и т.д.
```

### `src/main.cpp` — точка входа, «главная» программа

```cpp
void setup() {
    Serial.begin(115200);   // Открываем «консоль» для отладки через USB
    delay(500);             // Ждём 0.5 секунды — дать всему стартовать

    // Выводим в консоль информацию о плате
    Serial.printf("CPU:   %lu MHz\n", getCpuFrequencyMhz());   // 240 МГц
    Serial.printf("PSRAM: %lu KB\n", ESP.getPsramSize() / 1024); // 8192 КБ
    Serial.printf("Heap:  %lu KB free\n", ESP.getFreeHeap() / 1024); // ~300 КБ

    // Запускаем дисплей
    if (!Display::instance().begin()) {
        // Если дисплей не запустился — зависаем с ошибкой
        Serial.println("FATAL: display init failed");
        while (true) delay(1000);
    }

    // Тест: заливаем экран красным, зелёным, синим, чёрным
    Display::instance().fillScreen(0xF800); delay(400); // красный
    Display::instance().fillScreen(0x07E0); delay(400); // зелёный
    Display::instance().fillScreen(0x001F); delay(400); // синий
    Display::instance().fillScreen(0x0000);             // чёрный

    Serial.println("Boot OK");
}

void loop() {
    delay(5000);
    Serial.println("StarBoy alive"); // Раз в 5 секунд говорим "я жив"
}
```

**Что такое `Serial`?**
Когда плата подключена к компьютеру по USB, она может отправлять текст обратно. Это называется Serial Monitor — как чат с платой. Очень удобно для отладки: видишь что происходит внутри.

**Что такое `0xF800`?**
Это цвет в формате RGB565. Каждый цвет упакован в 2 байта (16 бит): 5 бит красного, 6 зелёного, 5 синего. `0xF800` = максимальный красный, 0 зелёного, 0 синего = чистый красный.

### `src/display/Display.h` — «интерфейс» модуля дисплея

`.h` файл — это как оглавление книги. Он не содержит реального кода, только **список того, что умеет делать дисплей:**

```cpp
class Display {
public:
    static Display& instance();   // Получить единственный экземпляр дисплея
    bool begin();                 // Инициализировать дисплей (вернёт false если сломан)
    Arduino_CO5300* gfx();        // Получить доступ к «сырому» рисованию (для глазок)
    void fillScreen(uint16_t color); // Залить весь экран цветом
    void setBrightness(uint8_t brightness); // Яркость от 0 до 255
};
```

**Зачем `static Display& instance()`?**
Это паттерн «синглтон» — в программе может быть только ОДИН дисплей (у нас одна плата, один экран). Синглтон гарантирует что мы не создадим случайно два объекта дисплея. Вызываешь `Display::instance()` — получаешь всегда один и тот же объект.

### `src/display/Display.cpp` — реальный код инициализации дисплея

```cpp
bool Display::begin() {
    // Шаг 1: создать «шину» — канал связи с дисплеем
    // QSPI = Quad SPI = разновидность быстрого последовательного интерфейса
    // Используем 4 провода данных одновременно (D0-D3) вместо одного
    _bus = new Arduino_ESP32QSPI(
        LCD_CS,   // GPIO10 — Chip Select: «я сейчас говорю с тобой»
        LCD_SCL,  // GPIO11 — Clock: тактирование (ритм передачи данных)
        LCD_D0,   // GPIO12 — провод данных №1
        LCD_D1,   // GPIO13 — провод данных №2
        LCD_D2,   // GPIO14 — провод данных №3
        LCD_D3    // GPIO15 — провод данных №4
    );

    // Шаг 2: создать объект-драйвер конкретного дисплея CO5300
    _gfx = new Arduino_CO5300(
        _bus,        // какой канал использовать
        LCD_RESET,   // GPIO8 — нога сброса (как кнопка reset)
        0,           // поворот: 0 = без поворота
        466,         // ширина в пикселях
        466,         // высота в пикселях
        6, 0, 0, 0   // смещение: контроллер CO5300 рассчитан на 480px,
                     // а наш экран 466px — сдвигаем на 6 пикселей
                     // иначе картинка будет съехана влево
    );

    // Шаг 3: запустить
    _gfx->begin();         // инициализация по протоколу QSPI
    _gfx->fillScreen(0);   // очистить экран (чёрный)
    _gfx->setBrightness(200); // яркость 200 из 255
}
```

**Что такое QSPI?**
Способ передачи данных от процессора к дисплею. «Quad» — четыре провода данных одновременно, что в 4 раза быстрее обычного SPI. Нам нужна скорость — экран 466×466 пикселей, каждый пиксель 2 байта = 434 КБ на один кадр. При 30 кадрах в секунду нужно передавать ~13 МБ/с.

**Почему col_offset = 6?**
Контроллер CO5300 рассчитан на экраны до 480×480. Но наш физический экран — 466×466. Разница 14 пикселей делится пополам: 7 слева + 7 справа. Но реально Waveshare сместил в одну сторону на 6 пикселей. Без этой цифры картинка на реальном железе будет смещена. Это было найдено в исходном коде примеров Waveshare.

### `src/eyes/Eyes.h` и `src/eyes/Eyes.cpp` — модуль анимированных глазок

Это главный UI StarBoy — два янтарных глаза на чёрном экране.

**Как выглядят глаза на экране:**
```
        ╭─────────────────────╮
       /                       \
      /    [ЛЕВЫЙ]  [ПРАВЫЙ]    \
     │       ( )      ( )       │
      \                         /
       ╰─────────────────────╯
```
Левый глаз — центр (158, 233), правый — (308, 233). Радиус радужки 65 пикселей. Экран круглый, углы за его пределами — просто чёрные.

---

**Как рисуется один глаз (4 шага за кадр):**

```
1. fillRect(...)          — стереть предыдущий кадр (только область глаза, не весь экран)
2. fillEllipse(cx, cy)    — нарисовать янтарную радужку
3. fillCircle(cx+dx, cy+dy) — нарисовать чёрный зрачок (dx/dy = смещение взгляда)
4. fillCircle(cx, cy-...)   — нарисовать чёрный круг сверху = веко
5. fillCircle(cx-20, cy-20, 5) — маленький белый блик (отражение света)
```

**Как работает веко — хитрость:**
Веко это не прямоугольник, а большой чёрный круг того же радиуса, что и глаз, сдвинутый вверх. Когда он высоко — он не перекрывает глаз (открыт). Когда опускается — перекрывает сверху, и граница получается естественно изогнутой (как настоящее веко, а не как прямая линия).

```
lidOpen = 1.0 → центр чёрного круга высоко → глаз полностью открыт
lidOpen = 0.0 → центр чёрного круга на уровне глаза → глаз закрыт
```

---

**Эмоции — это просто числа:**

```cpp
enum class Emotion { IDLE, HAPPY, ANGRY, SAD, SLEEPY, SURPRISED };
```

Каждая эмоция — набор трёх параметров:

| Эмоция | Веко (0=закрыто) | Высота радужки | Размер зрачка |
|--------|-----------------|----------------|---------------|
| IDLE | 1.0 (открыто) | 1.0 (круглый) | 1.0 (норма) |
| HAPPY | 0.75 (прищур) | 0.8 (сплющен) | 0.9 (меньше) |
| SLEEPY | 0.45 (тяжёлое веко) | 0.7 (сплющен) | 0.7 (меньше) |
| SURPRISED | 1.0 (открыт) | 1.15 (больше) | 1.3 (расширен) |

При смене эмоции глаза **плавно перетекают** из одного состояния в другое за ~0.4 секунды. Это называется LERP (линейная интерполяция): каждый кадр текущие значения чуть-чуть двигаются к целевым.

---

**Автоморгание:**

Каждые 2–5 секунд (случайно) запускается анимация моргания:
1. Веко закрывается за 120 мс
2. Держится закрытым 30 мс
3. Открывается за 150 мс
4. Планируется следующее моргание через случайный интервал

---

**Взгляд (`lookAt`):**

```cpp
Eyes::instance().lookAt(0.5f, 0.0f); // зрачки сдвигаются вправо
Eyes::instance().lookAt(0.0f, 0.3f); // зрачки сдвигаются вниз
```

Значения от -1.0 до +1.0. Позже гироскоп будет автоматически передавать сюда наклон устройства — и зрачки будут «следить» за горизонтом.

---

**Почему FreeRTOS задача, а не просто loop()?**

```cpp
// В setup() создаётся отдельная задача:
xTaskCreatePinnedToCore(eyesTask, "eyes", 4096, nullptr, 5, nullptr, 1);
```

`loop()` в Arduino работает на **ядре 0**. Задача глазок работает на **ядре 1**. Это значит:
- Глазки рисуются стабильно каждые 33 мс (~30 кадров/сек)
- Параллельно на ядре 0 можно обрабатывать Wi-Fi, звук, сенсоры — они не мешают друг другу

Это как два человека работают одновременно, а не один делает всё по очереди.

### `include/lv_conf.h` — конфиг библиотеки LVGL

LVGL (Light and Versatile Graphics Library) — это библиотека для создания интерфейсов: кнопки, текст, анимации. Мы будем использовать её для вспомогательного UI (статус Wi-Fi, уровень заряда). Для самих глазок — отдельная система прямого рендера.

`lv_conf.h` — файл с настройками LVGL. Самые важные:
- `LV_COLOR_DEPTH 16` — 16-битный цвет (RGB565, как у нашего экрана)
- `LV_COLOR_16_SWAP 1` — байты цвета нужно менять местами (особенность нашего дисплея по SPI)
- Включены только нужные виджеты (label, image, arc) — остальные выключены чтобы сэкономить место в Flash

```cpp
#define WIFI_SSID     "your_wifi_name"
#define WIFI_PASSWORD "your_wifi_password"
```

Это **шаблон** — сам файл безопасно хранится в репозитории. Настоящий файл (`secrets.h`) создаётся локально и в git **никогда не попадает** (занесён в `.gitignore`). Так API-ключи не утекут если репозиторий станет публичным.

Git — система версий кода. `.gitignore` говорит ему «эти файлы не трогай»:

## Ключевые понятия коротко

| Термин | Что это |
|--------|---------|
| **GPIO** | Пронумерованные контакты платы. GPIO10 — это «нога номер 10». |
| **QSPI** | Быстрый канал связи с дисплеем по 4 проводам одновременно. |
| **I2C** | Медленный канал для сенсоров (гироскоп, тач). Работает по 2 проводам. |
| **I2S** | Канал для аудио (микрофон, динамик). Специальный протокол для звука. |
| **PSRAM** | Внешняя оперативная память (8 МБ). Для буферов кадров и звука. |
| **Flash** | Постоянная память (8 МБ). Там хранится код прошивки. |
| **FreeRTOS** | Операционная система реального времени. Позволяет делать несколько вещей «одновременно» (рисовать глазки и слушать микрофон). |
| **Serial Monitor** | Окно в VS Code / PlatformIO где плата пишет отладочные сообщения. |
| **RGB565** | Формат цвета: 16 бит = 5 красный + 6 зелёный + 5 синий. |
| **Singleton** | Паттерн кода: «этого объекта может быть только один». |
| **lib_deps** | Список библиотек которые нужно скачать для проекта. |
| **build_flags** | Настройки компилятора: константы, режимы сборки. |
| **LERP** | Linear interpolation — плавный переход между двумя значениями. `lerp(0, 10, 0.5)` = 5. |
| **FreeRTOS Task** | Отдельный «поток» кода, работающий параллельно с остальными. Как отдельный процесс в ОС. |
| **Emotion enum** | Перечисление эмоций: IDLE, HAPPY, ANGRY, SAD, SLEEPY, SURPRISED. Каждая = набор параметров. |
| **lookAt(x, y)** | Сдвигает зрачки в сторону. -1..+1 по горизонтали и вертикали. |
